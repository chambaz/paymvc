# Ethereum / EVM / Foundry

A standalone payments demo with Solidity, React, TypeScript, and Viem. Ethereum, Base, Monad, and Robinhood share this implementation. Each user controls one disposable wallet. Addresses are the only identity. Credits use a zero-decimal OpenZeppelin ERC-20; fees use the selected network's native token.

## Run

Requirements: Node 24+, npm, and Foundry 1.7.1. Run commands from this directory.

```sh
npm ci
npm run contracts:build
npm run local
```

The local launcher starts Anvil at `127.0.0.1:8545` and the frontend at `http://127.0.0.1:5173`. Click **Create demo wallet**, then fund the displayed address:

```sh
cast rpc anvil_setBalance WALLET_ADDRESS 0xDE0B6B3A7640000 --rpc-url http://127.0.0.1:8545
```

Click **Start demo**. Registration allocates 100 credits and adds the address to the directory. A fresh user has no activity. Use a separate browser profile for a second user. Stop the launcher with Ctrl+C. Local chain state is disposable.

`npm run dev` defaults to Ethereum Sepolia. Select another public testnet with `npm run dev -- --network base`, `--network monad`, or `--network robinhood`. The same selection works for `deploy`, `test:live`, and `test:live:browser`. `PAYMVC_NETWORK` is the equivalent environment setting. Unknown names stop before use. Anvil is only for explicit local development and tests.

One production build contains all four public deployment records. `?network=base` selects Base on any origin. Without it, a network subdomain selects the network, so `base.paymvc.com` opens Base; other hosts use the build default (Ethereum). The same applies to the other names. The selected deployment must match the chain ID. The local launcher explicitly selects `public/local.json`; production builds exclude that Anvil configuration.

The dropdown links all nine networks. The local default ports are: Ethereum 5173, Solana 5175, Base 5177, Monad 5179, Stellar 5181, Sui 5183, Aptos 5185, Robinhood 5187, and Thruput 5189. Start each frontend that you want to reach; all EVM frontends run from this folder. `VITE_ETHEREUM_URL`, `VITE_BASE_URL`, `VITE_MONAD_URL`, and `VITE_ROBINHOOD_URL` point the dropdown at hosted sites instead, either one subdomain per network (as paymvc.com does) or one origin with the matching `?network=` parameter. ## Architecture

| Path                               | Responsibility                                                   |
| ---------------------------------- | ---------------------------------------------------------------- |
| `contracts/DemoCredits.sol`        | Standard ERC-20 with EIP-2612 permits and one-time allocations   |
| `contracts/PayMVC.sol`             | Registration, directory, transfers, requests, and activity       |
| `script/Deploy.s.sol`              | The Foundry deployment script for every network and Anvil        |
| `src/chain/config.ts`              | Deployment validation, RPC clients, and native amount formatting |
| `src/chain/session.ts`             | One local key, deployment-bound storage, exact amounts           |
| `src/chain/transactions.ts`        | Local signing, durable evidence, receipt reconciliation          |
| `src/chain/payments.ts`            | Registration, permits, native contract reads and writes          |
| `src/chain/generated/`             | The contract ABIs, generated by `npm run contracts:build`        |
| `src/hooks/use-demo.ts`            | Session state, Web Locks, cached reads, bounded recovery         |
| `src/components/payments-view.tsx` | Copyable presentation without signing or SDK calls               |
| `src/networks/index.ts`            | Network definitions: labels, faucets, explorers, ports, reserves |
| `deployments/`                     | Separate immutable app identities for each network               |

Viem does all chain work: local signing, contract reads, and writes. React Query, in the shared `use-demo.ts` hook, caches the reads. One dashboard read returns the balance and the activity at the same block.

Registration atomically adds directory membership and allocates 100 credits. It cannot repeat. The append-only directory returns at most 50 addresses per contract call, in registration order. The frontend loads five other users at a time. Reads use one block snapshot per page; one extra address read replaces the user's own entry when necessary. There is no indexer, automatic contact creation, or seeded activity.

Only the caller can send its credits. Only the intended payer can approve or decline a request. Outgoing requests have no response control. There is no owner, upgrade proxy, or privileged debit operation.

An entry's key is its creator and operation ID: `entries[from][operation]`. There is no global ID or counter. Each account's history stores these keys in creation order, and a request updates its state in place. `activity(account, before, limit)` returns the entries below the history index `before`, newest first. The frontend starts at `activityCount` and loads 50 records at a time; a new entry cannot shift a later page. Activity rows use `from:operation` as their ID.

### Contract interface

| Function                                             | Notes                                                       |
| ---------------------------------------------------- | ----------------------------------------------------------- |
| `register()`                                         | Membership, directory entry, and 100 credits, atomically    |
| `send(to, amount, operation, deadline, v, r, s)`     | Creates a `Paid` transfer and pays with the permit          |
| `request(payer, amount, operation)`                  | Creates a `Pending` request                                 |
| `approve(from, operation, deadline, v, r, s)`        | Only the intended payer; pays with the permit, marks `Paid` |
| `decline(from, operation)`                           | Only the intended payer; marks `Declined`, moves no funds   |
| `registered(account)`, `profileCount()`              |                                                             |
| `profiles(start, limit)`                             | Registration order; `limit` is 1 to 50                      |
| `entry(from, operation) returns (Entry)`             | Reverts with `NotFound` when there is no entry              |
| `activityCount(account)`                             |                                                             |
| `activity(account, before, limit) returns (Entry[])` | Newest first; `limit` is 1 to 50                            |

`Entry` is `{ from, to, operation, amount, kind, state }`, with `Kind { Transfer, Request }` and `State { Pending, Paid, Declined }`. The errors are `AlreadyRegistered`, `NotRegistered`, `InvalidParticipants`, `InvalidAmount`, `InvalidOperation`, `OperationUsed`, `NotFound`, `Unauthorized`, `NotPending`, and `InvalidPage`. Token failures use OpenZeppelin's ERC-20 errors, for example `ERC20InsufficientBalance`.

### Native deviations

- **Permits in `send` and `approve`.** On EVM the token sees PayMVC as the caller, so PayMVC needs an allowance to move the user's credits. Each payment carries an EIP-2612 permit for exactly its amount, so it is one transaction instead of an `approve` transaction and a payment.
- **`entry` reverts with `NotFound`.** Solidity has no `Option` type. The client treats that revert as "no entry".
- **`uint256` amounts.** This is the ERC-20 amount type. The contract still accepts only 1 to 1,000,000.

## Token model

Credits are a standard ERC-20 token, built on the OpenZeppelin ERC-20 contract with zero decimals. ERC-20 is the standard fungible token interface on EVM chains, so wallets, explorers, and other contracts can read and transfer credits without PayMVC code. Amounts are exact integers; the frontend never derives a balance from activity.

Only the PayMVC contract can mint `DemoCredits`. It allocates 100 credits once, at registration. External ERC-20 transfers change the actual balance but add no PayMVC activity.

`DemoCredits` also implements EIP-2612 permits (OpenZeppelin `ERC20Permit`). Before it builds a send or an approval, the browser signs a permit with the session key: owner, PayMVC as spender, the exact amount, the token's current nonce, and the maximum deadline, because EVM transactions do not expire. `send` and `approve` call `token.permit` and then `transferFrom` from the caller only. A permit that is already used, for example because someone copied it from a pending transaction and submitted it first, does not stop the payment: PayMVC ignores the failed `permit` call and uses the allowance that the permit set. Without a matching permit or allowance, the payment reverts and nothing changes. Decline needs no permit and no credits.

## Funding

Wallet creation saves one key before transactions start. The suggested reserve is the greater of the network's funding minimum and the current maximum fee per gas multiplied by the network's funding gas. The funding gas covers registration and the four payments of the shared scenario, with a margin: 5,000,000 gas on Sepolia, which prices new storage far higher (a request uses about 1.25M gas), and 1,500,000 gas on the other networks and on Anvil. Monad charges the gas limit, not the gas used. The funding minimum is 0.00005 ETH on Base Sepolia and 0.0005 of the native token on the other networks and on Anvil. Each network defines these values in `src/networks/index.ts`. Registration and later payments consume this reserve. Faucets may require sign-in or impose eligibility rules.

Keys and signed transaction evidence stay in browser local storage. Browser storage and Web Locks are scoped by chain, contract, and code hash. Switching back restores that network's wallet and journal on the same origin. A new hostname or port has separate browser storage. Sessions from earlier contract versions are not migrated.

## Confirmation and recovery

Web Locks permits one writer tab. Refresh restores the same wallet and journal. Reset removes local access; it cannot cancel transactions or remove chain state.

Every transaction is saved before broadcast. Unknown outcomes keep the original signed bytes and hash. Retry reconciles the original receipt or rebroadcasts those bytes; a saved transaction is never signed again, and no new permit is signed for it. The permit inside a saved transaction stays valid until it is used, because its nonce changes only when a permit is used and its deadline is the maximum. A rebroadcast therefore still pays. One successful mined receipt is confirmation, not finality; a later reorganization can change that result. Transactions have no application expiry. Definitive reverts permit explicit retry; a reverted payment also reverts its permit, so the retry signs a new permit with the same nonce. Uncertain outcomes do not permit a new payment.

Reconciliation reads `entry(from, operation)`. Confirmation needs the receipt and the expected entry: participants, amount, kind, and state.

Setup makes one automatic recheck after five seconds for a receipt timeout or delayed registration result. Interactive operations make one automatic recheck for delayed application results. Further recovery requires user action. The app verifies chain ID, bytecode hash, token address, registration membership, and expected payment results. Failed reads keep previous data with a stale indicator.

Robinhood is an Arbitrum Nitro L2. Standard gas estimation includes its execution and L1 data costs. PayMVC uses the same successful-receipt threshold as other EVM networks; this is a sequencer confirmation, not Ethereum finality. Recovery rechecks original receipts. The contracts do not depend on `block.number`, randomness opcodes, or L1 address aliasing. See Robinhood's [EVM differences](https://docs.robinhood.com/chain/differences-from-ethereum/), [fees](https://docs.robinhood.com/chain/gas-and-fees/), and [finality](https://docs.robinhood.com/chain/transaction-finality/).

## Deploy

Foundry deploys the contracts. The same script deploys to every network and to Anvil:

```sh
forge script script/Deploy.s.sol --rpc-url ethereum --broadcast \
  --skip-simulation --gas-estimate-multiplier 110 --private-key "$(cat .local/sepolia-deployer)"
```

The endpoint names are in `foundry.toml`: `ethereum`, `base`, `monad`, `robinhood`, and `anvil`. `npm run deploy -- --network NAME` runs that command with the network's key and then writes the public record. It reads `broadcast/Deploy.s.sol/CHAIN_ID/run-latest.json`, checks the deployment on chain, and writes `deployments/NETWORK.json`: chain ID, RPC URL, PayMVC and token addresses, deployment block, code hash, and faucet. `npm run local` uses the same script on Anvil and writes `public/local.json`.

The keys are `.local/sepolia-deployer` for Ethereum and `.local/NETWORK/CHAIN_ID-deployer` for other networks, with mode 0600. The script creates a key if none exists. Fund the printed address on the selected testnet, then rerun. The key goes to forge only and is never printed.

Foundry saves each transaction in the broadcast journal before it sends it. If a deployment stops, run `npm run deploy -- --network NAME --resume`; forge sends only the transactions that did not land, then the record is written. Keep the `broadcast/` folder until the record is written.

Forge estimates gas with the network's RPC (`--skip-simulation`) and adds 10%. Its local EVM can price state creation differently from a network: since its October 2026 upgrade, Sepolia charges about seven times the local gas for this deployment (13.8M gas). A larger margin would pass Sepolia's 16.78M per-transaction gas cap. `RPC_URL` overrides the endpoint for forge and for the record; do not put provider secrets in public deployment records.

Run `npm run build` after deployment changes.

## Verification

### Commands

```sh
npm run check
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:networks
npm run test:visual
```

Contract tests cover allocation, authorization, every canonical error, lifecycle transitions, permits (including a permit that someone else used first), decline without credits, entry lookup, the activity cursor when a record lands between pages, rollback, replay, directory bounds, and fuzzed conservation. Unit tests in `tests/unit/` cover exact amounts, session isolation, funding, network selection, directory cursors, and recovery. Browser tests use real Anvil transactions with independent users, desktop/mobile layouts, accessibility, persistence, reset, and failure paths. Browser suites run sequentially. Traces are disabled to keep signing keys out of artifacts.

Visual baselines live only in this implementation, because the view is byte-identical in every implementation (`conformance/verify.mjs` enforces this). `tests/visual/` screenshots the UI fixture in light and dark mode and needs no local chain. `npm run test:visual` compares and `npm run test:visual:update` regenerates the baselines. Both run in the Playwright Docker image, so Docker is required.

In the full repository, `npm run test:conformance` also compares local test-only snapshots with the common contract. This folder's local commands run independently after you copy it out of the repository.

### The networks

`npm run test:networks` checks the production build's network selection and wallet isolation.

The live commands run the shared scenario on the selected public testnet. Each command creates two independent users, A and B, and funds each one from the network's deployer key with the app's funding budget. The deployer journal saves each funding transfer before broadcast, and the next run reconciles it.

```sh
npm run test:live -- --network base
npm run test:live:browser -- --network base
```

- `npm run test:live` signs the scenario in Node: send, approval, decline, reverse request, and an external token transfer. It verifies balances 85/115 and four activity records for each user.
- `npm run test:live:browser` serves the production build (run `npm run build` first) on the network's port and runs the same scenario in the browser, on desktop and then on mobile. It also checks reload and reset.

Each command writes its result to `evidence/NETWORK.json` (for example `evidence/base.json`), in the format of `evidence.schema.json`. `chain` is the `test:live` result; `browser` has one result per viewport. A command replaces only its own result. If the deployment changed, the command starts a new file. Each result records the commit (`git rev-parse HEAD`), the date, the final balances and activity counts of A and B, and the transaction hashes in scenario order. `npm run check` validates every evidence file.

Run live commands from a clean working tree: if this folder has uncommitted changes outside `evidence/`, the command writes `.local/evidence-NETWORK.json` instead and prints a notice. Commit the evidence file after the run.

To test the live commands locally, start `npm run local`, then run `LOCAL=1 npm run test:live` and `LOCAL=1 npm run test:live:browser`. They use Anvil and the running frontend on port 5173, and write `.local/evidence-local.json`.

`LIVE_RUN` selects a fresh named run with new users. `LIVE_PORT` selects another preview port for the browser command. `LIVE_RPC_URL` overrides the RPC for funding and browser requests without changing deployment files or the production build; pass private provider URLs through the environment only. Private sessions and journals stay under `.local`. Evidence never contains keys, signed transactions, browser profiles, or traces.
